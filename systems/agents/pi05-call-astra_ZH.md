## 技术概览

若大型推理模型持续审查机器人策略，即使策略本身运行正常，也会增加延迟和 token 开销。该研究保留冻结的 π0.5 作为常规控制器，并训练轻量级 CALL 模块估计何时需要协助。只有触发条件满足时，GPT-6 Astra 才进入控制闭环，完成恢复后交还控制权。核心问题是：局部学习型触发器能否保留推理协助的收益，同时避免每步调用 Astra。

## 检测器输入与训练

冻结的 OpenPI `pi05_libero` 策略生成十步、每步七维的候选动作片段。CALL 读取同一次策略推理中的视觉语言表征、动作 token 特征、机器人状态以及动作片段统计量，并用小型多分支网络输出经过校准的求助概率。预测过程不需要额外调用外部模型。

训练样本结合正常推进的策略状态与 LIBERO-Recovery 中的失败状态。对每个保存的状态，重复运行仅由 π0.5 控制的后续轨迹，以估计基础策略完成任务的概率；完成概率越低，求助目标越高。论文报告跨任务划分的 5,055 个能力状态样本，并使用任务专用检测器和任务套件级后备检测器。这种监督依据策略的实际续行能力标注求助需求，而非仅凭图像异常判断。

## 控制权切换与恢复

常规执行时，系统从每个策略动作片段中执行五步，再重新查询 π0.5 与 CALL。持续触发要求最近五次求助分数中至少四次超过校准阈值；另设硬阈值用于立即触发。冷却期限制连续求助。控制权切换时，尚未执行的 π0.5 动作会被丢弃。

Astra 随后接收外部和腕部 RGB 图像、任务指令、实测机器人状态、策略候选动作及执行历史。它可以生成一段末端执行器修正，也可以不执行动作而直接交还控制权。执行层校验并将修正转换为 LIBERO 动作接口，执行后重新获取 π0.5 的候选动作，再恢复常规控制。因此，“咨询 Astra”“实际执行 Astra 动作”和“成功恢复”是不同事件。

## 评测与报告结果

论文评测 LIBERO-10、Object、Goal 和 Spatial 四个任务套件，每套十项任务、每项五个测试回合，共 200 个回合。混合系统成功 195/200（97.5%），纯 π0.5 成功 191/200（95.5%）。四个回合的差异主要来自 LIBERO-10；Object、Goal 和 Spatial 中两种方法的成功回合数相同。

系统在 61/200 个回合咨询 Astra，但只在 13/200 个回合实际执行 Astra 动作。四个任务套件合计，Astra 执行了 12.44% 的环境步；摘要中的 5.49% 仅对应 Object、Goal 和 Spatial。解读“按需介入”时必须区分这些分母。论文还报告 token 消耗与环境动作吞吐量，在比较推理延迟或成本时应与成功率一并考虑。

## 结果解读与使用条件

系统依赖冻结的 π0.5 权重、带策略能力标注的恢复状态、校准后的检测阈值、特定动作接口以及 Astra 服务。LIBERO 结果不能与持续审查式 Agent 在 RoboDojo 子集上的分数直接合并。复现时需明确咨询触发条件、实际介入的判定、Agent 保持控制权的时长，以及策略何时恢复执行。
