# 具身操作

[English](README.md) · [首页](../README_ZH.md)

具身操作方法的区别，首先在于模型预测什么，以及预测结果如何进入机器人控制闭环。本页按 VLA、世界动作模型（WAM）、Agent 式系统和抓取模型组织相关工作，并提供技术档案与评测基准入口。

## 四类方法概览

| 方法类型 | 输入与直接输出 | 在机器人系统中的作用 |
| --- | --- | --- |
| [VLA](models/vla/README_ZH.md) | 图像、指令及机器人状态 → 动作或动作片段 | 语言条件下的学习型控制策略 |
| [WAM](models/wam/README_ZH.md) | 观测及任务信息 → 与环境变化建模结合的动作 | 利用视觉动力学或未来预测训练的策略 |
| [Agent 式系统](agents/README_ZH.md) | 观测、任务、历史与工具 → 工具调用、运动目标或干预决策 | 围绕控制器进行决策与恢复 |
| [抓取模型](models/grasping/README_ZH.md) | 物体或场景几何 → 夹爪或灵巧手的候选抓取 | 为操作流程提供接触姿态建议 |

这些类别描述系统组件，并不互斥。例如，Agent 可以审查 VLA 轨迹，抓取模型可以提出由学习型策略执行的目标。

## 视觉—语言—动作策略（VLA）

VLA 根据视觉观测和语言目标生成机器人动作。接入具体平台时，相机与本体状态字段、动作表示及归一化方式必须与目标机器人匹配。以下工作展示了不同的动作生成和适配方案。

| 方法 | 动作生成方式 | 主要接口特点 |
| --- | --- | --- |
| [OpenVLA / OpenVLA-OFT](models/vla/openvla_ZH.md) | 原版使用离散动作 token；OFT 使用连续动作与动作片段 | 基于 Open X-Embodiment 的模型系列，微调方案不同 |
| [SmolVLA](models/vla/smolvla_ZH.md) | 流匹配生成连续动作片段 | 紧凑模型，与 LeRobot 数据和机器人工具集成 |
| [openpi：π0 / π0-FAST / π0.5](models/vla/openpi_ZH.md) | π0、π0.5 使用流匹配；π0-FAST 使用自回归 FAST token | 同一仓库发布多个权重及机器人专用数据变换 |
| [GR00T N1.7](models/vla/gr00t-n1.7_ZH.md) | 流匹配动作 Transformer | 机器人形态配置与策略服务流程 |

**适用场景：** 已有带动作标注的示教，研究目标是视觉语言条件下的策略学习或任务适配。基础权重通常还需针对目标机器人微调。

**比较条件：** 记录具体 checkpoint、相机视角、本体状态、动作单位、归一化、微调数据、动作片段长度及控制频率。[VLA 专题对比](analysis/vla/README_ZH.md)说明架构和资源差异，[评测条件](analysis/vla/benchmark-notes_ZH.md)说明协议如何对齐。

## 世界动作模型（WAM）

WAM 将动作学习与环境变化建模联系起来。核心差别在于世界建模发生的环节：它可以是训练目标、推理时显式生成的未来观测，或两者兼有。生成视频质量与实际任务成功率属于不同结果。

| 方法 | 世界与动作如何结合 | 执行动作时的行为 |
| --- | --- | --- |
| [Unified World Models](models/wam/uwm_ZH.md) | 视频与动作联合扩散，分别设置噪声等级 | 同一权重通过不同条件设置支持策略和动力学预测 |
| [DreamZero](models/wam/dreamzero_ZH.md) | 联合预测未来视频与动作 | 执行短动作片段后，用新观测修正预测 |
| [Fast-WAM](models/wam/fast-wam_ZH.md) | 训练时使用视频预测 | 直接生成动作，推理时不显式生成未来视频 |
| [OpenWAM](models/wam/openwam_ZH.md) | 模块化研究骨干网络、信息流和预训练 | 发布 OpenWAM-α 预训练策略 |

**适用场景：** 研究场景动力学、视频预测或无动作标注视频对操作策略的作用。具体方法可用于动作控制、世界预测，或两者结合。

**比较条件：** 明确视频骨干网络、训练数据、动作表示、预测范围、去噪步数、执行时是否生成视频，以及实测推理延迟。某个方法更快，可能来自省略视频生成环节，而不只是动作网络规模不同。

## Agent 式具身操作

Agent 式系统在机器人工具或学习型策略外增加决策层。关键设计问题是**控制权如何分配**：谁提出运动，谁验证运动，何时接管，又何时交还控制。

| 系统 | Agent 的决策 | 控制边界 |
| --- | --- | --- |
| [GPT-6 Astra as an Embodied Policy](agents/gpt-as-policy_ZH.md) | 直接给出末端目标，或接受、修正 π0.5 提案 | 宿主程序验证目标并执行受约束的动作片段 |
| [π0.5 + Astra 按需介入](agents/pi05-call-astra_ZH.md) | 本地 CALL 检测器触发后负责恢复 | 冻结的 π0.5 承担常规控制 |
| [GPT-Policy](agents/gpt-policy_ZH.md) | 根据示教和反馈发出结构化机器人工具请求 | 工具适配器将请求转成可执行运动 |

**适用场景：** 任务分解、指令变化或失败恢复需要高层决策，而固定底层策略不足以独立处理。Agent 仍依赖控制器限位、坐标转换与机器人反馈。

**比较条件：** 除任务成功率，还应报告 Agent 调用频率、实际执行的干预、决策延迟、工具校验，以及模型思考期间环境是否继续演化。只进行咨询但未执行修正，与实际接管控制不是同一事件。

## 抓取模型

抓取模型估计末端执行器在何处、以何种姿态接触物体。一个候选抓取不等于完整的抓取搬运规划；标定、可达性、接近运动、手指闭合和结果验证仍是独立步骤。

| 方法 | 末端执行器与输出 | 主要区别 |
| --- | --- | --- |
| [AnyGrasp](models/grasping/anygrasp_ZH.md) | 平行夹爪；六自由度抓取姿态 | 点云检测与时序跟踪 |
| [UniDexGrasp](models/grasping/unidexgrasp_ZH.md) | 灵巧手；候选姿态与执行策略 | 将目标生成与目标条件控制分开 |
| [DexGraspNet 2.0](models/grasping/dexgraspnet-2_ZH.md) | 灵巧手；场景条件下的抓取姿态 | 考虑目标周围的杂乱物体 |
| [DexGrasp Anything](models/grasping/dexgrasp-anything_ZH.md) | 灵巧手；生成式抓取姿态 | 在扩散采样中加入物理约束 |

**适用场景：** 平行夹爪检测可用于拣选系统中的抓取选择；灵巧手方法关注多关节接触与姿态生成，部分方法还包含独立执行策略。

**比较条件：** 先对齐手部模型和场景条件，再分别报告姿态有效性、无碰撞比例、仿真抬升成功率及真机任务完成率。这些指标测量的是不同阶段。

## 完整系统如何比较

比较两种方法时，可以沿一次观测追踪完整控制链路：

1. **观测：** 记录相机、本体状态、任务指令与历史信息。
2. **预测：** 明确模型直接输出的是动作、视频、抓取、工具调用还是干预决策。
3. **执行：** 记录解码、归一化、运动规划、控制器约束与动作时序。
4. **再次观测：** 明确何时使用新观测替换预测，以及推理期间环境是否继续运行。
5. **评测：** 对齐机器人、训练数据、checkpoint、任务分布、随机种子、成功判据和指标汇总方式。

[评测基准索引](benchmarks/README_ZH.md)介绍各套件测量的能力及其协议对结果解读的影响。
