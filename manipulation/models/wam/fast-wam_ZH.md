## 技术概览

Fast-WAM 将世界动作模型中经常同时出现的两个因素分开研究：训练时利用未来视频预测学习表征，以及执行时先显式生成未来画面再选择动作。该方法保留视频预测训练目标，但执行时省略未来视频生成。因此，其运行接口接近直接动作策略，而内部表征仍受到世界建模监督。

## 输入与模型架构

模型以当前视觉观测和任务语言为条件，通过视频 VAE 编码图像，并生成机器人动作片段。其主干采用预训练 Wan2.2-5B 视频扩散 Transformer，另设动作生成模块。共享注意力的 Mixture-of-Transformer 架构使动作 token 能利用视觉信息，同时保留两种模态各自的处理路径。

训练时，模型联合优化加噪的未来视频 token 与动作 token。注意力掩码阻止动作 token 读取未来视频 token，避免动作预测依赖部署时不可获得的信息。推理时移除未来视频 token：视频主干对当前画面的潜变量执行一次编码，动作模块再基于这一表征生成动作片段。这与先合成未来画面、再据此生成动作的 WAM 流程不同。

## 受控变体

论文比较直接推理方案、视频与动作联合去噪方案、先想象后行动方案，以及不进行视频联合训练的方案。这些对照旨在区分训练目标的作用与未来画面生成的收益和开销。另有已发布的 Optional IDM 权重，可在 `idm` 模式下先预测未来视频再生成动作，或在 `first_frame` 模式下直接根据当前帧预测动作，无需重新训练。

## 评测与报告结果

论文评测 LIBERO、RoboTwin 2.0 和真机毛巾折叠。在 RoboTwin 2.0 上，论文报告 Fast-WAM 的平均成功率为 91.8%，联合生成变体为 90.6%，先想象后行动变体为 91.3%，移除视频联合训练后为 83.8%。这些受控对照支持论文在相应实验条件下的结论：训练阶段的视频监督比推理时显式生成未来画面更关键；不能据此推断所有机器人和任务分布都具有相同排序。

原项目主页报告单张 RTX 5090D V2 32 GB GPU 上的推理时间为 190 毫秒，并在所报告的真机设置中与 810 毫秒的先想象后行动变体比较。代码仓库还记录了后续在其他 GPU 上的推理优化。硬件、编译设置、文本嵌入缓存及是否包含视频解码均影响延迟，不应混用不同配置下的数字。

## 公开实现与比较条件

官方仓库提供 LIBERO 和 RoboTwin 的训练及评测流程，支持 LeRobot 2.1 与 3.0 数据格式。已发布权重包含 LIBERO、RoboTwin 模型及 Optional IDM 变体，每个权重配有相应的数据统计文件。复现报告分数时，需匹配数据配置、权重与归一化统计、评测任务集合、动作调度参数和运行设置。论文中的真机展示采用特定平台，不代表其他机器人可直接接入。

## 视频训练为何不必对应视频推理

Fast-WAM 将未来视频预测作为训练信号，同时通过注意力约束阻止动作 token 读取未来视频 token。这样，动作分支学习使用当前观测，而不依赖部署时无法获得的未来信息。训练完成后，控制路径可省略未来视频生成：动作模块直接根据当前帧特征对动作片段去噪。该设计将视频监督可能带来的表征收益，与显式生成未来画面的推理延迟分开研究。

论文设置了若干受控变体：去掉视频联合训练、在推理时联合生成视频与动作，以及先生成未来画面再预测动作。这些实验针对特定任务和配置检验架构选择；其结果不能推出所有场景都不需要显式未来预测。

## 使用公开权重

官方仓库发布任务专用 checkpoint 及对应的归一化统计量。部署时需配套使用观测布局、动作映射、去噪设置和评测客户端。Optional IDM 权重还提供 `idm` 与 `first_frame` 两种模式，但不意味着所有 Fast-WAM 权重均可使用这两个路径。Fast-WAM 适合研究控制延迟较敏感、同时希望保留视频预测训练信号的操作任务。
