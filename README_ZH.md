## 🌐 关于项目

具身智能发展迅速，但更多信息并不一定带来更好的理解。论文使用不同的数据集、评测协议、硬件与报告口径；许多仓库只展示成功结果，却没有记录运行条件和失败过程。

**OpenEmbodied 希望把分散的资源转化为结构化、可比较、可验证的知识。**

本项目不止收集链接，而是记录一项工作解决了什么问题、方法如何运行、证据是否充分、复现需要付出什么成本，以及它在哪些条件下不再适用。

> [!IMPORTANT]
> OpenEmbodied 目前处于基础建设阶段。我们将先建立内容标准和首批旗舰专题，再逐步扩展覆盖范围。

## ✨ 为什么是 OpenEmbodied

| 常见问题 | OpenEmbodied 的处理方式 |
| --- | --- |
| 论文列表很长，但缺少上下文 | 使用统一结构的 Research Profile |
| 不同工作的结果难以比较 | 补充数据集、基准、指标与评测协议 |
| “开源”但复现条件不透明 | 明确代码、权重、数据、许可、算力与环境状态 |
| 只展示成功 Demo | 记录限制、失败模式与尚未解决的问题 |
| 教程过时后无人察觉 | 标注最后验证时间和证据等级 |

## 🧭 四条内容主线

```text
Track → Understand → Verify → Choose
追踪前沿 → 理解工作 → 验证结果 → 做出选择
```

### 🔭 Frontier Watch｜前沿追踪

聚焦 VLA、世界模型、机器人操作、导航、人形机器人、数据与评测的重要进展。每项内容必须引用原始来源，并说明它为什么值得关注。

### 🗂️ Research Profiles｜研究档案

用统一结构记录论文、模型、数据集与系统：

- 问题定义与研究动机；
- 方法与关键设计；
- 数据、基准、指标与算力；
- 代码、权重、许可与开放状态；
- 实验结果、限制与失败模式；
- 相关工作与最后验证时间。

### 🧪 Reproduction Reports｜复现报告

保存环境、命令、硬件、输出、指标差异、修复过程与失败尝试，而不只保留最终成功截图。

### ⚖️ Comparison Guides｜对比指南

持续维护横向比较页面，回答实际问题：

- 哪个 VLA 适合当前机器人、数据和算力预算？
- 哪个 Benchmark 真正在评测目标能力？
- 哪些项目真正开放且可以复现？
- 哪些实验结果能够公平比较？

## 🧾 证据等级

每项技术内容都可以标注证据等级。等级表示 OpenEmbodied 已验证到哪一步，不代表对原工作的质量评分。

| 等级 | 含义 |
| --- | --- |
| **L0 — 已阅读** | 已阅读并整理原始资料 |
| **L1 — 可安装** | 文档中的环境可以完成安装 |
| **L2 — 可运行** | 官方或最小 Demo 已成功运行 |
| **L3 — 已复现** | 在记录条件下复现了公开指标或实验 |
| **L4 — 已验证** | 在真实硬件或额外平台、任务上完成验证 |

## 🎯 首批建设重点

第一阶段聚焦三个相互关联的方向：

1. **VLA Landscape**：模型架构、训练数据、动作表示、机器人形态、算力、开放程度与评测结果。
2. **Benchmark Map**：任务、协议、指标、可比性与常见误读。
3. **Reproduction Reports**：透明记录环境、结果、偏差和失败过程。

选择较窄的起点是有意为之。少量可靠、值得反复引用的专题页面，比大量浅层条目更有价值。

## 🗺️ 覆盖方向

| 方向 | 代表性主题 |
| --- | --- |
| 视觉—语言—动作模型 | 通用策略、动作表示、多模态对齐 |
| 世界模型与规划 | 预测模型、行动规划、长时程推理 |
| 机器人操作 | 抓取、灵巧操作、双臂与移动操作 |
| 具身导航 | 空间推理、建图、探索与 VLN |
| 运动与人形机器人 | 全身控制、运动操作、动作学习 |
| 数据与评测 | 机器人数据集、仿真环境、基准与评测协议 |

## ✅ 收录标准

每项内容应当：

- 引用原始论文、官方仓库、项目页面和数据集；
- 区分作者结论、我们的理解与独立复现结果；
- 记录公开时间和最后验证时间；
- 明确代码、权重、数据与许可证是否真正开放；
- 在比较数值前说明评测条件；
- 记录限制和负面结果；
- 保持便于浏览，同时提供足够的验证信息。

## 🤝 参与贡献

OpenEmbodied 欢迎内容纠错、原始资料更新、Research Profile、Benchmark 笔记与复现报告。

一项有价值的贡献应尽量包含：

- 官方来源与公开时间；
- 所属研究方向；
- 客观简介与收录理由；
- 代码、权重、数据和许可证状态；
- 可用的评测或复现证据；
- 已知限制与尚未解决的问题。

贡献模板将在第一版仓库结构中提供。在此之前，可以通过 Issue 推荐资源或提交纠错。
